## 1. 기술 스택

| 영역 | 선택 | 상태 |
|---|---|---|
| 사이트 생성 | Astro (정적 빌드) | 채택, 구현 전 |

| 슬라이드 | Swiper 11 | 채택, 목업 검증용 사용 |

| 임시 호스팅 | GitHub Pages | 사용자·대표 확인용, 저장소 공개 여부 미결 (§5) |

서버, DB, 로그인, 결제는 두지 않는다.

## 2. 구조

```text
GitHub 저장소 (dev → main)
   │  GitHub Actions: Astro 빌드
   ▼
GitHub Pages (임시) ── 정적 HTML/CSS/JS/이미지
   ▲
   │  arawon.github.io/raregen
사용자, 대표
```

도메인 연결 시 최종 호스팅을 결정한다. 정적 빌드 결과물이므로 호스팅을 바꿔도 사이트 코드는 거의 바뀌지 않는다.

계획 중인 디렉터리:

```text
src/
  layouts/      공통 레이아웃
  components/   Nav, Footer, Cta, 페이지 공통 블록
  pages/        index, about, products/*, lab, contact
  data/         제품, 브랜드 데이터
  styles/       디자인 토큰, 모션
public/         이미지
scripts/        brief, check-device.sh
```

| 페이지 | 경로 |
|---|---|
| 메인 | `/` |
| 회사소개 | `/about/` |
| 취급 브랜드 | `/products/brands/` |
| 마그네틱 비드 | `/products/magnetic-bead/` |
| 기업 소모성 자재 | `/products/mro/` |
| 제품 목록 | `/products/list/` |

| 견적 문의 | `/contact/` |

### 레이아웃 규칙

- 페이지 상단: 왼쪽 큰 제목(3 비율), 오른쪽 설명(2 비율)
- 섹션: 구분선 아래 왼쪽 라벨(1 비율), 오른쪽 내용(2.4 비율)
- 제품정보 페이지에는 공통 탭을 둔다.
- 작은 화면에서는 한 열로 쌓고 가로 스크롤이 생기지 않게 한다.

## 5. 임시 호스팅 제약 (GitHub Pages)

목적은 사용자와 대표의 확인이다. 최종 호스팅은 도메인 연결 시 결정한다.

- **접근 제한이 없다.** 비공개 저장소라도 일반 플랜의 Pages 주소는 아는 사람 누구나 열 수 있다. 접근을 막으려면 GitHub Enterprise의 비공개 Pages나 다른 접근 제어 서비스가 필요하다.
- 임시 기간에는 주소를 두 사람에게만 알리고, `noindex`와 `robots.txt`로 검색 노출을 줄인다. 이는 비밀 보호 수단이 아니다.
- **저장소가 현재 비공개다.** 비공개 저장소에서 Pages를 쓰려면 유료 플랜이 필요하다. 무료로 쓰려면 저장소를 공개해야 한다.
- 공개 시 문서와 커밋 이력 전체가 공개되므로, 저장소에 비밀값과 개인 연락처를 넣지 않는다.
- 서버 측 리다이렉트를 쓸 수 없다. 기존 URL은 정적 페이지나 `404.html`의 스크립트로 이동시킨다.
- 서버 코드가 없으므로 문의 기능은 외부 서비스가 필요하다.
- GitHub Pages는 온라인 사업 운영이나 전자상거래 사이트를 주목적으로 쓰는 것을 약관에서 제한한다. 최종 호스팅으로 계속 쓰려면 도메인 연결 전에 최신 약관을 확인한다.
- 임시 주소는 `https://arawon.github.io/raregen/` 이므로 Astro의 `base` 설정이 필요하다. 도메인 연결 시 `base`를 제거한다.

- 스톡 이미지, 제품·실험실 사진 촬영 (필요 시)

## 8. ADR

### ADR-001. Astro 정적 사이트로 전환
- **상태:** 채택 (2026-11-05)
- **배경:** 쇼핑몰 기능을 없애고 소규모 정적 페이지와 문의 창구만 남기기로 했다.
- **결정:** Astro로 정적 빌드한다. 서버와 DB를 두지 않는다.
- **결과:** 운영 부담이 작다. 공통 Nav와 데이터 재사용이 가능하다.

### ADR-002. 확인 단계는 GitHub Pages, 최종 배포는 도메인 연결 시 결정
- **상태:** 채택 (2026-11-05), 최종 호스팅과 저장소 공개 여부 미결
- **배경:** 사용자가 GitHub 호스팅을 제안했고, 당분간 사용자와 대표만 확인한다. 배포 방식은 도메인을 연결할 때 정하기로 했다.
- **결정:** GitHub Actions로 빌드해 Pages에 임시 배포한다.
- **결과:** §5의 제약을 따른다. Pages 주소에는 접근 제한이 없고, 저장소 공개 또는 유료 플랜 중 하나를 골라야 한다.

### ADR-003. 문의 기능을 `준비중`으로 시작
- **상태:** 채택 (2026-11-05)
- **결정:** 문의 페이지에 `준비중`을 표시하고 발송 기능을 만들지 않는다.
- **결과:** 개인정보 수집과 스팸 대응을 공개 초기에 다루지 않는다. 기능을 열 때 개인정보처리방침을 함께 준비한다.

### ADR-004. 제품은 구매 절차 없이 표시
- **상태:** 채택 (2026-11-05)
- **배경:** 처음에는 브랜드·제품군 소개만 두기로 했으나, 사용자가 제품을 보여 주기로 변경했다.
- **결정:** 9개 제품을 정적 데이터로 관리하고 카드, 사양 팝업, 정렬, 견적 문의 연결만 제공한다. 가격은 일단 표시한다.
- **결과:** 가격 변경 시 데이터를 수정해야 한다. 인기순은 정적 값이다.

### ADR-005. 모션은 Swiper, AOS, FLIP으로 구성
- **상태:** 채택 (2026-11-05)
- **배경:** 사용자가 Swiper와 AOS를 지목했고, 정렬 시 위치 이동이 보이기를 원했다. Decagon은 소스 기준으로 GSAP, Swiper, Lottie를 사용한다.
- **결정:** 슬라이드는 Swiper, 스크롤 등장은 AOS, 정렬 이동은 FLIP, GNB는 CSS와 SVG로 구현한다. Lottie와 GSAP은 필요가 생길 때 검토한다.
- **결과:** 라이브러리가 적다. 목업은 뷰어 호환을 위해 AOS CSS를 자체 스크립트로 구동했으므로, 실제 사이트에서 AOS 원본의 동작을 다시 확인한다.
